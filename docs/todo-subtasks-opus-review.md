# 할 일 세부 항목 — 구현 및 검토 기록

갱신일: 2026-10-13

## 현재 상태

큰 할 일 아래 한 단계의 세부 체크리스트를 추가했습니다. Opus의 두 번째 검토 결과는 **반영 가능**이며, 주요 지적 사항 해결과 26개 스위트·640개 테스트 통과를 확인받았습니다.

그 후 낮은 등급의 지적 3건과 기존 NUL 바이트를 추가로 정리했습니다. 이 마지막 변경은 **Opus의 두 번째 검토 이후 변경**입니다. Codex가 전체 **26개 스위트·641개 테스트 통과**, 변경 코드 Babel 변환, `git diff --check`를 확인했습니다.

코드는 로컬 변경 상태입니다. 커밋·네이티브 빌드·OTA·스토어 배포는 실행하지 않았습니다. 공유 JavaScript여서 iOS와 Android 양쪽에 영향을 줍니다. 배포 플랫폼·방식·런타임은 배포 시점에 확인해야 하며, 이 기록은 배포 승인을 뜻하지 않습니다.

## 요구 및 동작

```text
[ ] 수학 공부                 세부 1/2
    [x] 문제집 p12–17 풀기
    [ ] 전에 오답 복습하기
```

- 제목 아래 '세부 항목 추가'로 항목을 입력·수정·삭제합니다.
- 부모와 세부 항목은 독립적으로 완료 처리합니다. 세부 항목을 전부 완료해도 부모는 자동 완료되지 않습니다.
- 부모 완료 시 세부 목록을 숨기고 완료 개수는 유지합니다. 부모 완료 해제 시 기존 체크 상태 그대로 목록을 다시 표시합니다.
- 세부 항목은 부모의 과목·목록·기한·반복 설정을 따릅니다. 통계와 집중 시간도 부모 기준입니다.
- 새 입력은 최대 20개·각 200자로 제한합니다. 로드 과정에서 기존 데이터를 잘라내지 않습니다.
- 빈 입력 행이 있으면 새 행을 추가하지 않고 기존 빈 입력창에 포커스를 옮깁니다.
- 새 반복 실행 항목은 미완료 체크로 시작합니다. 일반 미완료 항목은 다음날 체크를 유지하고, 고정 반복 항목은 날짜 리셋 때 체크를 초기화합니다.
- 템플릿/실행 항목 편집은 저장 시점 실행 항목의 체크를 세부 ID별로 보존합니다. 새 세부 항목만 미완료입니다.
- 오답노트에는 메모 뒤에 `· 문제집 풀기 (완료)` / `· 오답 복습 (미완료)`처럼 평문으로 저장합니다. 기존 노트는 소급 변경하지 않습니다.

| 지적 | 처리 |

## 두 번째 검토 이후 추가 수정

1. **토글의 원본 보존**: 읽기 헬퍼가 제외한 항목도 원본 배열에는 남깁니다. 화면에 표시된 대상 인덱스 하나만 체크해, ID가 없거나 중복된 다른 항목이 체크 동작만으로 삭제되지 않게 했습니다. 중복 ID는 첫 유효 항목만 바꾸며 관련 회귀 테스트를 추가했습니다.
2. **평문 노트**: 마크다운 체크 문법 대신 `· 내용 (완료/미완료)`를 사용합니다.
3. **빈 입력창 포커스**: 입력창 ref를 ID별로 보관하고, 빈 행이 있으면 그 입력창을 포커스합니다. 실제 키보드와 스크롤 가시성은 아래 실기기 확인 대상입니다.
4. **NUL 바이트**: `reviewNotes.js`에 원래 있던 NUL 2개를 소스의 `\u0000` 이스케이프로 변경했습니다. 문자열 런타임 값은 동일합니다. 이전 Git 객체에는 NUL이 있으므로 해당 변경을 볼 때 `git diff --text`가 필요할 수 있습니다.

## 검증 및 한계

```powershell
npm.cmd test -- --runInBand
git diff --check
git diff --text -- src/utils/reviewNotes.js
```

현재 결과: **26개 스위트·641개 테스트 통과**. 화면 및 유틸의 Babel 변환도 통과했습니다. 새 테스트 파일은 아직 untracked일 수 있으므로 일반 `git diff`와 별도로 읽어야 합니다.

저장 테스트는 실제 storage 함수와 모의 AsyncStorage로 실행했습니다. 실기기 강제 종료, 실제 백업 파일 선택 및 복원, 화면·접근성 동작을 검증한 것은 아닙니다.

기존 한계: 자정 리셋으로 원본 실행 ID가 삭제된 뒤 수정 폼을 저장하면 편집이 무시됩니다. 이번 범위에서 수정하지 않았습니다.
