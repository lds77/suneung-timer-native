## 1. 문제 — 실기기에서 확인된 것

사용자 메일 피드백("큰 할 일 아래 세부 항목으로 나눠 체크하고 싶다")으로 만든 기능을 안드 실기기에서 써 봤다.

1. 첫 시도: 시트 제목 아래 **'⊕ 세부 항목 추가 (0/20)' 글자를 기능으로 인식하지 못해** 메모 칸에 적었다
   → `560026e`에서 **빈 세부 칸 1개를 미리 깔아** 해결했다. 실기기에서 "기본 1개는 좋다"고 확인됨
2. **이번 문제**: 첫 칸을 채운 뒤 **두 번째 칸을 만드는 방법을 알 수 없다.**
   현재 방법은 둘뿐이고 둘 다 숨어 있다.
   - 키보드의 **'다음' 키** — 키보드 키가 '항목 추가'라는 것을 알려 주는 단서가 화면에 없다
   - **'세부 항목 추가 (n/20)' 글자** — 1번과 같은 이유로 버튼처럼 보이지 않는다

목표: **설명을 읽지 않아도** 사용자가 세부 항목을 여러 개 넣는 법을 바로 알게 한다.

## 3. 요구 설계 — '끝에 항상 빈 칸 하나' (자동 늘어나는 체크리스트)

구글 Keep·Apple 미리 알림의 체크리스트와 같은 방식이다. **사용자는 '보이는 빈 칸에 적는다'만 알면 된다.**

### 3-1. 동작

1. **마지막 칸에 글자가 들어가는 순간, 그 아래에 새 빈 칸이 자동으로 생긴다.**
   - 새 칸은 **포커스를 빼앗지 않는다** (지금 입력 중인 칸에 그대로 머문다)
   - 채운 칸이 `MAX_SUBTASKS`(20)에 도달하면 더 만들지 않는다
2. **끝의 빈 칸은 항상 정확히 하나**를 유지한다.
   - 사용자가 마지막 채운 칸을 지워 끝에 빈 칸이 둘 이상 되면, **맨 끝 쪽 여분부터** 지워 하나만 남긴다
   - 중간에 비어 있는 칸(앞쪽 칸 글자를 지운 경우)은 **입력 중일 수 있으므로 자동으로 지우지 않는다.** 저장 시 `normalizeSubtasks`가 버린다
3. 키보드 **'다음'** 키는 새 칸을 만드는 대신 **바로 아래 칸으로 포커스를 옮긴다.**
   아래 칸이 없으면(끝 빈 칸에서 눌렀거나 20개를 다 채운 경우) 키보드를 닫는다
4. **'세부 항목 추가 (n/20)' 버튼은 없앤다.** 끝 빈 칸이 그 역할을 하므로, 남겨 두면 누를 때 아무 칸도
   안 생겨(이미 빈 칸이 있으니 포커스 이동만 함) 오히려 헷갈린다. `addSubtask`·`newSubtaskId`·
   `autoFocus` 관련 코드는 쓸모가 없어지면 함께 정리한다
5. X 버튼: **채운 칸에만** 보인다. 빈 칸에는 숨기되 자리(현재 `width: 38`)는 유지해 정렬을 맞춘다

### 3-2. 보이는 안내 (사용법)

- 빈 칸 placeholder
  - 첫 칸(채운 칸이 하나도 없을 때): **"체크할 세부 항목 (선택)"** — 현재 문구 유지
  - 그 뒤 끝 빈 칸: **"세부 항목 더 적기"**
- 세부 목록 아래 안내 한 줄(`fontSize: 12`, `T.sub`). 채운 칸 수에 따라 바꾼다.
  - 0개: 표시 안 함
  - 1개 이상: **"적을 때마다 아래에 새 칸이 생겨요. 저장하면 하나씩 체크할 수 있어요."**
  - 20개(상한): **"세부 항목은 20개까지 적을 수 있어요."**
- 기존 문구 "세부 항목과 큰 할 일은 각각 완료 표시할 수 있어요."는 위 안내로 **대체**한다

### 3-3. 순수 로직은 함수로 빼서 테스트한다

행 목록을 맞추는 규칙(3-1의 1·2)을 `src/utils/todoUtils.js`에 순수 함수로 둔다. 이름과 시그니처 예시:

```js
// rows: 폼의 세부 행 [{ id, text, done }]. 끝 빈 칸을 정확히 하나로 맞춘다(상한이면 0개).
// 채운 칸·중간 빈 칸·ID·순서는 건드리지 않는다. makeId는 테스트에서 주입한다.
export const syncSubtaskRows = (rows, max, makeId) => { ... };
```

- 폼은 `onChangeText`에서 갱신한 목록을 이 함수로 한 번 통과시켜 `setSubtasks`한다.
  열릴 때(87–88행)도 같은 함수로 초기 목록을 만든다
- 테스트(`src/utils/__tests__/todoSubtasks.test.js`에 추가)로 최소 아래를 고정한다
  - 빈 목록 → 빈 칸 1개
  - 마지막 칸을 채우면 → 빈 칸 1개 추가, 기존 행은 **같은 객체·같은 ID**
  - 끝에 빈 칸이 3개 → 1개로 줄어듦 (맨 끝 쪽부터 제거)
  - 중간 빈 칸은 유지
  - 채운 칸이 20개 → 빈 칸을 추가하지 않음 / 20개 + 빈 칸 1개가 들어오면 빈 칸 제거
  - 공백만 있는 칸(`'  '`)은 빈 칸으로 취급
  - 기존 데이터의 채운 칸이 20개를 넘어도 **잘라내지 않는다**(입력 상한은 새 입력에만 — 이미 확정된 규칙)

## 4. 하지 말 것

- 첫 빈 칸이나 새로 생긴 칸에 **자동 포커스를 주지 않는다** — 시트를 열면 제목 칸이 포커스를 가져야 한다(현재 `autoFocus`)
- 세부 항목의 체크(`done`)를 폼에서 다루지 않는다 — 저장 시 `mergeSubtaskDone`이 저장된 상태를 쓴다
- `TodoSection.js`(목록 화면)·`useAppState.js`·저장 형식은 이번 범위가 아니다
- 집중탭 **한 줄 빠른 추가**에 세부 입력을 넣지 않는다(별도 판단 — 이번 범위 밖)

## 5. 회귀 확인 (코드로 확인할 것)

- 수정 시트: 세부 항목이 있는 할 일을 열면 **채운 칸들 + 끝 빈 칸 1개**로 시작하는지
- 저장 결과가 이전과 같은지: 빈 칸은 버려지고, 채운 칸의 ID가 유지돼 `mergeSubtaskDone`이 체크를 이어받는지
- 반복 템플릿 편집 경로(`editTodoInPlace`) 테스트가 그대로 통과하는지
- 20개 상한 상태에서 '다음' 키가 오류 없이 키보드를 닫는지
