**심사 결과**: 리젝. Submission ID `e3c17b24-fd63-4564-a50c-cad453dbf0f4`, 심사 기기 iPad Air 11"(M3).

> Recently, the Chinese Ministry of Industry and Information Technology (MIIT) requested that
> CallKit functionality be deactivated in all apps available on the China App Store. …

**원인**: `modules/focus-shield/ios/FocusShieldModule.swift`의 `import CallKit` + `CXCallObserver`.
2026-08-01에 **iOS 전화 수신 시 이탈 오탐을 고치려고** 넣은 것이다(CLAUDE.md 전화 처리 절).

### ★관측 전용이라는 사실은 방어가 되지 않는다★
`CXCallObserver`는 통화를 **읽기만** 하고 `CXProvider`/`CXCallController`(통화 UI·VoIP 제공)는
전혀 안 쓴다. 그래도 리젝이다 — 심사는 **바이너리가 CallKit을 링크했는지**를 보지 통화 UI 유무를
보지 않는다. "우린 VoIP 앱이 아니다"로 다투지 말 것.

### ★이 제약은 영구적이다★
- `import CallKit`이 코드에 남아 있는 한 **중국 본토를 다시 켜는 순간 재리젝**된다.
  배포 지역을 손댈 일이 생기면 이 절을 먼저 볼 것.
- **build57(1.0.40)도 같은 CallKit을 갖고 있다** — 지역 해제 없이 1.0.40으로 갈아타도 똑같이 리젝된다.
  즉 지역 해제는 **어느 빌드로 재제출하든 선결 조건**이다.

- 적용 10곳: 플래너 계획/고정일정, 일정편집 고정일정·계획, 설정 리마인더,

  유실된다(버튼 press와 blur의 순서가 플랫폼마다 다름). min/빈칸 보정만 blur에서
- **컴포넌트가 친 값을 말없이 바꾸지 않는다** — minValue 하한을 넣었다가 되돌렸다(be9b6ed).

### ★이번에 밟은 함정: 안드 Modal은 별도 창이라 'pan'이 안 먹는다★

`app.config`의 `softwareKeyboardLayoutMode: 'pan'`은 **메인 액티비티 창에만** 적용된다.
RN `Modal`은 별도 Dialog 창이라 키보드가 올라와도 밀리지 않아 입력칸이 그대로 묻힌다.
휠 시절엔 키보드를 안 써서 드러나지 않다가 타이핑으로 바꾸며 표면화(1d904d0).
→ 시간 입력이 있는 모달 4곳에 `KeyboardAvoidingView(behavior="padding")`.
스터디룸이 이미 같은 함정을 같은 방법으로 풀어두고 주석까지 남겨둔 상태였다.

곁들여 드러난 것:
- 일정편집 '과목' 모달은 **세로 ScrollView가 아예 없었다** — 시트 92% 고정이라 넘치는
  내용(목표 시간·시간 입력)이 잘려 접근 불가. 이번 개편 전부터 있던 문제
- 설정 리마인더 시트는 `position:'absolute'`라 KAV의 padding이 밀어내지 못한다 → flex-end 배치
- '특정 시간에 배치' 토글을 켜면 새로 생긴 시간 줄이 잘린 채 나옴 → 켤 때 그 줄까지 스크롤
  (카드 탭·스위치 탭 **두 경로 모두** 필요, 57c8222)

## 4.7 ★오답노트 첨부가 안드 자동 백업을 깨뜨리던 문제 (2026-08-02) — **네이티브 빌드 필수(OTA 불가)**★

**발견**: "사진·오디오를 많이 쓰면 어떻게 되나"라는 질문에서 상한을 세어보다 드러남.
동영상 얘기가 아니라 **이미 배포된 사진 첨부(1.0.38~)만으로 걸리는 문제**였다.

- 노트당 5장 상한은 있지만 **노트 개수·총 용량 상한이 없다**
- 첨부는 `documentDirectory`(= `files/`)에 쌓이고, 이 폴더는 안드 자동 백업 대상
- 안드 자동 백업은 **앱당 25MB 상한**, 넘으면 백업이 통째로 실패
- 1600px·q0.6 압축 사진이 장당 200~400KB → **사진 꽉 채운 노트 ~17개면 25MB**
- 백업이 실패하면 `allowBackup: true`로 지키려던 것이 무너진다 —
  재설치 시 **익명 uid(스터디룸 계정)와 공부 데이터 복원이 조용히 안 됨**
  (계정 영속 1단계, 2026-07-19 승인). 사용자는 원인을 알 방법이 없다
- 확인: 이 프로젝트에는 백업 제외 규칙이 **아예 없었다**(매니페스트에 `allowBackup="true"`만)

**해결**: `plugins/withAttachmentsNotBackedUp.js` — 첨부 폴더만 클라우드 백업에서 제외.
`res/xml/data_extraction_rules.xml`(API 31+)와 `backup_rules.xml`(API 30-)을 생성하고
매니페스트 `<application>`에 연결한다. AsyncStorage(uid·공부 데이터) 백업은 그대로.
기기 간 직접 전송(device-transfer)은 용량 제한이 없어 **제외하지 않는다**(새 폰엔 사진도 따라감).

- 잃는 것 없음: JSON 백업/복원(`storage.js` BACKUP_KEYS)도 노트 기록만 담고 이미지 파일은
  애초에 안 옮긴다. 자동 백업이 사진을 옮기던 유일한 경로였고 그마저 25MB에서 깨졌다
- prebuild로 생성 확인 완료 (매니페스트 속성 2개 + res/xml 파일 2개)

**확인 항목 (다음 네이티브 빌드에서)**
- [ ] `adb shell dumpsys backup` 또는 재설치 복원으로 uid·공부 데이터가 살아오는지
      (사진 첨부를 25MB 넘게 만든 상태에서 — 예전엔 여기서 백업 자체가 실패했다)
- [ ] 재설치 후 오답노트 **기록은 살아 있고 사진만 비는지** (의도된 동작)
- [ ] Play 검토 화면 '지원 기기 변경사항' 이상 없는지 (권한 추가는 아니지만 습관적으로 확인)

★**설정 문구는 이 빌드와 함께 나가야 한다**★ — '백업/복원에는 포함되지 않아요'는
플러그인이 실린 빌드에서만 사실이다. 구 런타임(1.0.38/1.0.39)에 이 문구만 OTA로 보내면
거짓말이 된다(거기선 여전히 백업에 들어가고 25MB에서 깨진다).

**후속(미구현)**

  네이티브 작업 필요. iOS는 uid가 키체인에 있어 계정 영속은 안전하고, 남는 문제는
  사용자 iCloud 용량 소모뿐이라 후순위
- 오디오 첨부: expo-audio가 이미 있어 새 의존성 0개. `RECORD_AUDIO` 권한이

  플러그인이 반드시 필요**(규칙 12). iOS는 녹음 시 오디오 세션 카테고리가 바뀌므로
  재생 중인 백색소음을 멈췄다 되돌려야 한다

## 4.8 ★사진까지 담는 백업(zip) (2026-08-02) — **안드·iOS 전항목 통과**. 네이티브 빌드 필수(OTA 불가)★

**왜**: 4.7에서 첨부를 안드 자동 백업에서 제외하면서, 사진이 새 폰으로 옮겨가는 경로를
정리해보니 **온전한 길이 하나도 없었다**.

| 경로 | 사진이 따라가나 |
|---|---|
| 앱의 JSON 백업 | ✗ 노트 기록만, 이미지 파일은 안 담김 |
| 아이폰 → 아이폰 (iCloud/빠른 시작) | ○ (iOS는 제외 안 함) |
| 안드 → 안드 (기기 간 직접 전송) | ○ (device-transfer는 일부러 안 뺌) |
| 안드 → 안드 (클라우드 백업만) | ✗ 4.7 이후 |
| **안드 ↔ 아이폰 (기종 변경)** | **✗ 어떤 경로로도 안 감** |

**해결**: 백업 파일 하나(zip) 안에 `backup.json` + `attachments/`를 함께 담는다.
기존 흐름(내보내기 → 카톡·드라이브 저장 → 새 폰에서 파일 선택)이 그대로 유지되고
기종 변경까지 해결된다. `src/utils/backupArchive.js` (순수 로직 테스트 11개).

- ★**성립 근거: 노트는 첨부의 파일명만 저장한다**★(attachments.js) — 같은 이름으로
  새 폰의 앱 폴더에 되돌려 놓으면 링크가 그대로 살아난다. 경로를 저장했다면 불가능했다.
  **이 설계를 바꾸지 말 것**
- 압축은 `react-native-zip-archive@9`(New Arch **TurboModule**, 2026-07 유지보수 중).
  파일 경로로 직접 압축하므로 메모리 안전 — 순수 JS zip(jszip/fflate)은 파일을 base64로
  메모리에 올려야 해서 **정작 사진이 많은 사용자에게서 터진다**
- 내보낼 때 사진 포함 여부를 묻는다(장수·용량 표시). '기록만'은 예전과 똑같은 JSON 한 장
- 복원은 **매직바이트로 판별**(`UEsDB`) — 카톡·드라이브를 거치며 이름이 바뀌어도 맞고,
  **옛 .json 백업도 그대로 복원된다**(하위호환)
- 되돌리는 파일은 **복원할 노트가 참조하는 것만** — 손상·조작된 아카이브가 엉뚱한 파일을
  앱 폴더에 심는 것 방지(`filesToRestore`)
- zip이 폴더 이름을 엔트리 경로에 포함하는지는 플랫폼/버전마다 다를 수 있어,
  압축 해제 후 `backup.json`을 루트와 한 겹 안쪽에서 찾는다(`findRoot`) — 의존하지 않는다

**확인 항목 (다음 네이티브 빌드에서)**
- [x] 사진 있는 상태에서 '데이터 백업' → '사진도 함께' → zip이 만들어지고 공유되는지
- [x] 그 zip을 **다른 기기**에서 복원 → 노트와 **사진 썸네일까지** 살아나는지
- [x] '기록만' 백업 → .json → 복원 정상 (예전과 동일)
- [x] ★**예전에 만들어둔 .json 백업 파일도 복원되는지**★ (하위호환 — 실사용자가 갖고 있다)

- [x] 복원 취소 시 임시 폴더가 정리되는지

## 4.9 ★오답노트 음성 메모 (2026-08-03) — **안드·iOS 전항목 통과**. 네이티브 빌드 필수★

### ★플랫폼 재생 호환이 이 기능의 핵심 제약★

백업 zip으로 안드↔아이폰 기종 변경을 커버(4.8절)했기 때문에, **안드에서만 재생되는 포맷이
들어오면 그 커버가 깨진다**(아이폰에서 복원해도 음성만 안 들림). 두 곳에서 막았다.

1. **녹음**: `expo-audio`의 `RecordingPresets`를 **쓰지 않는다**. `LOW_QUALITY`가 안드에서
   `.3gp` + AMR-NB로 녹음하는데 iOS가 AMR 재생을 지원하지 않는다.
   → 양 플랫폼 m4a(AAC) 모노 64kbps로 직접 지정(분당 약 0.5MB). **테스트가 이 조건을 지킨다**
2. **파일 첨부**: 확장자 화이트리스트 `m4a·mp3·aac·wav`. 안드는 ogg·flac·amr을 재생하지만
   iOS는 못 하므로 첨부 단계에서 거절(이유를 사용자에게 말해준다)
   - 용량 상한 **10MB** — 녹음은 3분으로 묶이지만 남의 파일은 몇십 분짜리도 들어온다.
     백업 zip에 그대로 담기므로 여기서 안 막으면 백업이 못 쓰게 커진다

### 이번에 드러난 결함 2건 (음성이 없었으면 안 보였을 자리)

- ★**편집기가 첨부의 필드를 흘리고 있었다**★ — 노트를 열고 저장할 때 `{ file }`만 뽑아
  배열을 다시 만들어서 음성의 `type`·`durationMs`가 사라지고 **사진으로 변했다**
  (썸네일 자리에 빈 칸, 재생 불가). `normalizeAttachments`로 한 곳에서 정하고 테스트로 고정
- ★**목록 카드 썸네일이 '첫 첨부'를 Image로 그렸다**★ — 음성이 첫 번째면 빈 칸.
  첫 '사진'을 쓰고, 사진 없이 음성만 있으면 마이크 아이콘. 배지는 사진+음성 합계

### 그 밖의 설계 결정

- **녹음 중 집중 사운드 정지 → 끝나면 복원**(`useAppState.suspendSounds/resumeSounds`).
  iOS는 녹음 시작 시 오디오 세션 카테고리가 바뀌어 재생이 죽거나 백색소음이 녹음에 섞인다.
  ★`settings.activeSounds`는 건드리지 않는다★ — 지우면 저장까지 되어 사용자의 선택이 영구 손실.

- **진행바 + 탭해서 구간 이동**: 줄마다 플레이어를 따로 둔다(`AudioMemoRow`). 부모가 imperative
  플레이어 하나로 돌리면 진행 상태를 못 그린다. 동시 재생 방지는 부모의 `playingFile`이 주도
- 3분 도달 시 자동 정지(사용자 정지와 겹쳐 두 번 저장되는 것은 `stoppingRef`로 방지),

### ★후속: 결과 모달이 '전 항목 합계'를 공부 시간으로 보여주던 문제 (실기기 제보)★

  중도 종료 경로가 그대로 재사용하고 있었다.
