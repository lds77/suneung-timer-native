아래 숫자와 상태는 작성 시점 기록이다. 시작할 때 저장소와 콘솔에서 다시 확인한다.

## 무엇을 내보내는가

결과 화면의 건너뛰기를 시간 수정·기록 삭제와 한 줄로 옮겼다. 아이폰에서 시간 수정을 누르다 건너뛰기가 눌려
시간을 못 고치는 일을 사용자가 두 번 겪었다.

- 파일: `src/screens/focus/ResultModal.js` (미커밋)
- 배치: 시간 수정 | 기록 삭제 | 건너뛰기, 칸 높이 44, 완료 버튼과 간격 8
- 확인: Jest 통과, 사용자 안드로이드 미리보기 APK 실기기 통과 (2026-11-01)
- **아이폰 실기기는 미확인이다.** 증상이 아이폰에서 났으므로 TestFlight 확인이 필요하다

## 할 일 순서

### 1. 코드 커밋

1. `npm test`를 돌린다. 실패하면 멈추고 보고한다
2. 변경 파일을 babel로 파싱해 확인한다. Jest는 이 화면을 불러오지 않는다
3. 한국어 메시지로 커밋한다. 본문에 왜 고쳤는지 적는다

### 2. 버전 올리기

`app.config.js`:

| 항목 | 지금 | 다음 |
|---|---|---|
| version | 1.0.42 | **1.0.43** |
| ios.buildNumber | 60 | **61** |
| android.versionCode | 74 | **76** (이 저장소는 짝수 관행) |

`npx eas-cli build:list`로 번호가 안 겹치는지 먼저 본다. 커밋한다.

★`runtimeVersion`이 `appVersion` 정책이라 새 버전은 런타임이 달라진다. OTA는 이번 범위가 아니다. 쏘지 않는다.

### 3. 빌드 (이 지시로 승인됨)

```
npx eas-cli build --platform ios --profile testflight --non-interactive --no-wait
npx eas-cli build --platform android --profile production --non-interactive --no-wait
```

- 지난번(1.0.42)과 같은 프로필이다. `eas.json`에서 확인한다
- 진행 확인은 `npx eas-cli build:view <ID>`. ★이 명령에는 `--non-interactive`가 없다. 붙이면 실패한다
- `TMP`·`TEMP`를 `C:\tmp`로 둔다. 사용자 경로에 한글이 있어 node가 죽을 수 있다

### 4. iOS TestFlight 업로드 후 사용자 확인

```
npx eas-cli submit --platform ios --id <빌드ID> --profile production --non-interactive
```

Apple 처리가 끝나면 **사용자에게 아이폰 확인을 요청하고 답을 기다린다.**

- 결과 화면에서 세 칸이 한 줄로 나오는가
- 시간 수정을 여러 번 눌러도 건너뛰기가 안 눌리는가
- 시간 수정·기록 삭제·건너뛰기가 각각 동작하는가
- 글자를 키워도 안 잘리는가

### 5. App Store 심사 제출

업데이트 내용:

```
공부 완료 화면에서 시간 수정을 누르다 건너뛰기가 눌리던 문제를 고쳤습니다.
시간 수정, 기록 삭제, 건너뛰기를 한 줄로 정리하고 누르는 영역을 넓혔습니다.
```

App ID `6759892516`. 사용자 크롬(Claude in Chrome)으로 한다. 로그인은 사용자가 직접 한다.

★이번 세션에서 겪은 함정:
- 새 버전 항목은 「iOS 앱 버전 ▾」 드롭다운의 「iOS 앱 +」에서 만든다 (좁은 창)
- **새 항목에서 프로모션 문구가 비어 나온다.** 이전 버전 값을 확인해 다시 넣는다
- **빌드 추가 창에 이전 빌드가 미리 선택될 수 있다.** 61을 직접 고르고 저장 뒤 다시 읽는다
- 기존 값이 있는 칸은 클릭, 전체 선택, 입력 순서로 넣는다. 끝나면 JS로 값을 읽어 확인한다
- 제출 패널에서 **항목 수를 눈으로 센다.** 「심사를 위해 제출」은 추가 확인 없이 바로 제출된다
- 키워드·설명·스크린샷은 바꾸지 않는다. 출시 방식도 이전 버전 설정 그대로 둔다
- 크롬 연결이 「not in tab group」「Couldn't determine which page」 오류를 번갈아 낸다. 그대로 재시도하면 된다. 실패한 호출은 실행되지 않았다

iOS 제출 전 아이폰 확인을 건너뛰지 않는다. 문제가 나오면 멈추고 보고한다.

### 6. Play 프로덕션 제출

1. EAS 빌드의 AAB를 `dist/yeolgong-1.0.43-vc76.aab`로 받는다
2. 패키지·버전·서명을 확인한다
3. Play Console 열공메이트 프로덕션 새 버전 화면을 연다
4. **AAB 업로드는 사용자에게 요청한다.** 크롬 도구는 10MB 제한이라 올릴 수 없다. 끌어다 놓기를 부탁한다
5. 출시 노트는 위 문구를 쓴다. 「이전 버전에서 복사」로 옛 문구가 들어가지 않게 한다
6. 번들 사양과 지원 기기 변동을 vc74와 견준다
7. 게시 개요의 **변경 항목을 하나씩 센다.** 넣지 않은 항목이 있으면 멈추고 묻는다
8. 사용자가 제출 지시를 했지만, Play는 항목 수와 경고를 보여 주고 「제출」 한마디를 받은 뒤 누른다
